# 作品追加スキル

書名（日本語でも原題でも可）から、翻訳を始められる状態までを整える。

## 手順

### 1. 作品の特定とパブリックドメイン確認

- 著者・原題・原語・著者の没年を特定する
- 没年から保護期間を判断（多くの法域で没後70年。**2026年時点なら1955年以前没なら概ね安全**）。
  微妙な場合（1950年代後半没、戦時加算、翻案元の権利など）は判断をユーザーに提示して確認する
- 対象は**原文からの新訳**が作れる作品のみ。既存の日本語訳が PD でも、それを取り込むことはしない

### 2. workId とカタログ登録

- workId は短い英小文字スラッグ（例: crime, metamorphosis, pride）
- `src/data/works.json` にエントリ追加:
  `title` / `author` / `authorOriginal` / `sourceLang`（ISO 639-1）/ `sourceTitle` / `sourceRef`（底本の書誌）

### 3. 原文の取得

**原文（外国語の本文）を自分の出力として長文で書き出さない。** 必ず curl でファイルに直接落とす
（APIの出力フィルタが書籍長文の逐語再現を検知してブロックするため。入力として読むのは問題ない）。

優先順:
1. **原語版 Wikisource**（露 ru. / 独 de. / 仏 fr. / 英 en. など）。
   `action=opensearch` でページ名を探し、`action=parse` で章ごとに取得
   → `source/wikisource/<chapterId>.api.json` に保存
   → `npx tsx tools/wikisource-to-paragraphs.ts <api.json> <workId> <chapterId> <章ラベル> <order>`
2. **Project Gutenberg**（原語のプレーンテキスト/HTML。翻訳版を取らないこと）
   → `source/gutenberg/` に保存し、`tools/wikisource-to-paragraphs.ts` を手本に
   同じ出力形式のコンバータを書いて `tools/` に追加する（段落1対1、`em` フラグ保存）
3. FB2 がある場合は `tools/fb2-to-paragraphs.ts`

底本の版（初版か決定版か等）と取得元URLを `sourceRef` / `sourceUrl` に必ず記録する。

### 4. 作品別台帳の作成（`src/data/works/<workId>/`）

- `style-guide.json` … crime のものを雛形に、**その言語・作品に合わせて書き換える**。
  最低限含めるもの:
  - 文体（常体/敬体）、段落1対1、既存邦訳の参照禁止、通貨・度量衡は音写して語注に回す
  - **音写規則**（global.rules に明文化）: その言語の名前をカタカナ化する原則
    （露: アクセント音節に長音・в はヴ系 / 英・独・仏: 慣用表記の採用基準 等）
  - **一人称の表記方針**: 漢字/かなまで指定する（既定: 粗野は「おれ」で「俺」不使用、
    丁寧・公式は「私」で「わたし」不使用。訛り・引用など例外は明記）
  - `people.<id>.firstPerson` … 人物ごとの一人称・口調。登録時は仮置きでよいが、
    **最初の1章の翻訳で確定させてから残りの章に進む**（章ごとに決め直すと必ず割れる）
  - `names` … people.json に載せない脇役・地名の音写台帳（`"カタカナ表記": "原語"`）。
    空 `{}` から始め、翻訳エージェントの「新規」報告を随時反映する
- `people.json` … **確実な主要人物だけ**を最初に登録（名・通常表記・原語表記・別称・立場）。
  別称（愛称・敬称形）は翻訳を進めながら人間が確定する。推測で埋めない
- `glossary.json` … 空 `{}` から始めてよい。翻訳後に `/translate` の注釈候補抽出で拡充

### 5. 検証ツールの言語対応

`tools/check-alignment.ts` の数詞・否定・文分割の辞書は現状ロシア語+日本語のみ。
新しい `sourceLang` を初めて扱うときは、その言語の数詞語彙・否定語・文末記号を追加して
`sourceLang` で切り替えるよう拡張すること（作品カタログの `sourceLang` を読んで分岐）。

`tools/check-consistency.ts`（固有名詞・一人称の表記ゆれ検査）は日本語側のチェックなので
言語対応なしでそのまま使える。台帳（people.json / style-guide の names・terms）が
充実しているほど検出精度が上がる。

### 6. ビルド確認と引き継ぎ

- `npm run build` が通ること（スケルトンのみで訳文ゼロの章は content/ に置かない。
  訳文が1段落でも入ってから章JSONを作る）
- ここまで終えたら「`/translate <chapterId>` で翻訳を開始できる」と報告する。
  最初の1章（短編なら全体）だけ訳して所要時間を計測し、続きに進むかはユーザーが決める

## 注意

- 1作品目の M3 原則を新作品にも適用する: まず1章（短編は1本）を完成させ、実測してから拡げる
- サイトのフッター表示は works.json の `sourceRef` から自動で出る。底本を書かずに公開しない
