# 階層ズーム・リーダー

長い文章を、地図のように拡大・縮小して読めるようにするレイヤー。
作品全体 → 部 → 章 → 節 → 段落 → 本文と連続的に降りていき、いつでも引ける。
系譜としては Ted Nelson の stretchtext（別ページに飛ぶのではなく、テキストがその場で伸縮する）。

> **これは本文を読まずに済ませるための要約生成器ではない。**
> UIの役割は「戻るための道具がそこにあると分かること」。
> 機能の判断で迷ったら「読み通せるようにするための道具か」で判断する。
> ただし読者がどう読むか（要約で復習する、興味のある節だけ精読する等）は設計で縛らない。

解いている問題:

- 長編の途中で話の筋を見失う
- 数週間空けて再開したときに、どこまで読んだか掴めない
- 読み終えた後に全体の構造を俯瞰したい
- 興味のある部分だけを選んで精読したい

## 階層とデータ

```
作品（overview）        src/content/overviews/<workId>.json
 └ 部（parts）          同上（部を持たない作品では階層ごとUIから消える）
    └ 章（outline）     src/content/outlines/<chapterId>.json
       └ 節（sections） 原文に存在しない編集判断の区切り。5〜15段落目安
          └ 段落        既存の章データ（src/content/chapters/）を範囲参照するだけ
```

設計の要点:

- **章データは不可侵。** 要約レイヤーは段落IDを参照するだけで、本文側は節を知らない。
  節は後から切り直される前提（`boundaryStatus: proposed → approved`）。
- **段落IDは一度振ったら変えない**（既存ルールのまま。既読管理と範囲参照が依存する）。
- 参照切れ・節の非連続・分量超過はビルド（content.config の zod）と
  `tools/merge-outline.ts` の両方で落とす。
- 要約が無い階層があっても壊れない。全階層が埋まる前から動く。

## 分量の規定（いちばん重要な設計判断）

ズームアウトしても情報量が減るのではなく、**粒度が粗くなって範囲が広がる**。
地図の縮尺と同じで、どのズームでも画面の情報密度は一定に保つ。

| 階層 | 目安 | 上限（超えるとビルドが落ちる） |
|---|---|---|
| 作品 | 400字 | 600字 |
| 部 | 400字 | 600字 |
| 章 | 300字 | 450字 |
| 節 | 150字 | 225字 |
| 段落 | 40字 | 60字（かつ本文より短いこと） |

段落要約が本文より長くなる場合は作らない（省略する）。

## ネタバレの封じ込め（genre: fiction）

**各要約は、その範囲の終端（`coversUpTo`）までに読者が知り得た情報だけで書く。**

- `coversUpTo` はツールが機械的に付与する（節=範囲終端、章=章末、部・作品=`chapterId#pid`）
- 生成はボトムアップ（段落→節→章→部→作品）。上位は下位の要約だけを材料にするので、
  範囲より先の情報が構造的に混入しない
- 生成エージェントには**対象章の本文だけ**を渡す（他章・原文・既存アウトラインを読ませない）。
  ただしモデルは作品を事前知識として知っているため、指示だけでは完全には防げない。
  そこで `tools/check-summaries.ts` が人物台帳（people.json）を語彙として
  **「初出が coversUpTo より後の人物への言及」を FAIL** として検出する
- 作品全体の要約は結末を含むため、UIでは既定で畳み、「結末までの内容に触れます」と明示して開かせる

## ステータス

要約は4段階: `draft`（生成しただけ）→ `machine-checked`（check-summaries が全部通った）→
`human-reviewed`（人が読んだ）→ `verified`（本文と照合済み）。

- ステータスは**UIには出さない**（未確認バッジ・提案段階の注意書きは画面のノイズなので廃止。
  段落の `status` と同じ扱いで、レビュー工程だけが見る内部状態）
- 昇格は `--promote`（→machine-checked）と人手（それ以上）。マージツールは
  human-reviewed 以上の要約と approved の節区切りを上書きしない

## パイプライン（ビルドでLLMを呼ばない。結果は必ずコミット）

```bash
npx tsx tools/export-ja.ts <chapterId>|--all   # 章の ja 本文をマークアップ抜きで書き出す（エージェント入力）
# ↓ 生成は Claude Code セッション内のエージェントが行う（source/outlines/INSTRUCTIONS.md 参照）
npx tsx tools/merge-outline.ts <chapterId> source/outlines/<chapterId>.json  # 検証つきマージ
npx tsx tools/merge-overview.ts <workId>       # 部・作品要約（source/outlines/part-*.txt 等）のマージ
npx tsx tools/check-summaries.ts <workId> [chapterId ...] [--promote]        # 機械ふるい→昇格
```

エージェントの手順書は `source/outlines/INSTRUCTIONS.md`。
1章＝1エージェントで、段落要約→節区切り→節要約→章要約をボトムアップに作り、
merge-outline を exit 0 まで通す（翻訳パイプラインと同じ受け口方式）。
部要約は「その部の章要約だけ」、作品要約は「部要約だけ」を材料に作る。

## UI

- **構造ビュー** `/works/<workId>/` — 部→章→節の要約ツリー。各所に「本文を読む」導線。
  章・部の既読率メーター。フィクションの作品要約は既定で畳む
- **stretchtext（読書画面）** — ページ遷移なしでその場で伸縮する。**既定はズームアウト**:
  要約を持つ節はまず要約カードだけが見え、カード（または見出し）を押して初めて本文にズームインする。
  ひらいた節は localStorage（`ecb:open:<chapterId>`）に記憶。読書位置・リンク先（#pNNN）の節は自動でひらく。
  「すべての節をひらく／たたむ」で一括切替。段落の「要約」ボタン（長押しでも）でその場に差し込む。
  章の頭に「ここまでのあらすじ」（前章までの章要約。coversUpTo 設計により先の展開を含まない）
- **現在位置バー** — ツールバー直下に作品全体を章幅=段落数で並べ、部の切れ目・既読の塗り・
  現在位置マーカーを表示。タップでその章へ（実質的な目次）
- **前後の章** — 読書画面の末尾に「← 前 / 次 →」と章名。部をまたぐ場合も order 順でつながる。
  1章しかない作品（短編）では出さない
- **既読管理** — 段落が1.5秒以上画面に表示されたら既読（localStorage、`ecb:read:<workId>`）。
  スクロールで飛ばした分は数えない。**要約を読んでも既読は付かない**
- 展開・収縮のトリガはすべて `<button>` ＋ `aria-expanded`。フォーカスリングは消さない
