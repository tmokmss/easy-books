# 読解支援リーダー 実装指示書

パブリックドメインの古典を、日本語訳＋読解支援レイヤー付きで読ませる静的サイト。
Astro で組み、GitHub Pages に配信する。

> 元指示書からの変更点（2026-08 実装時）:
> - 対象をロシア文学に限定せず「パブリックドメインの古典全般」に一般化
> - リポジトリ名は `easy-classic-books`（`base` も同名）
> - 段落の原文フィールドは `ru` → `src` に改名し、作品カタログ（`works.json`）＋
>   作品別データディレクトリ（`src/data/works/<workId>/`）構成に変更
> - 原文取得の実装は Wikisource コンバータが先行（FB2 コンバータも併備、出力形式は同一）
> - 人物の原語表記フィールドは `cyr` → `original` に一般化

## 0. 前提と背景

日本語読者が古典文学で挫折する原因は3つある。このプロジェクトが解くのは1と2で、3は解かない。

1. 訳文が古い（例: 米川訳は1930年代、工藤訳は1960年代）
2. 構造的なノイズ。ロシア語の姓名+父称+愛称の呼び分け、当時の官職・貨幣・地理など
3. 原文そのものの難しさ。長い独白、意図的な冗長さ

3を平易にすると別の作品になる。触らない。

**この製品の中心価値は訳文そのものではなく、読解支援レイヤーである。**
UIの判断で迷ったら、この一文に戻ること。

## 1. スコープ

### やること（v1）
- 対象: ドストエフスキー『罪と罰』第一部 第一章のみ
- 原文から日本語訳を作る変換パイプライン（オフライン実行、成果物をコミット）
- 注釈データ（人物・語注）の管理とレビュー用ツール
- 読むためのWebサイト（Astro、静的生成、GitHub Pages）

### やらないこと（v1）
- 全41章の翻訳。1章あたりのコストを測ってから判断する
- ログイン、サーバサイド、DB
- ビルド時のLLM API呼び出し（再現性のため）
- 原文の対訳表示。データ構造だけ将来入る余地を残す（`src` フィールド）

## 2. データ設計

### 本文（`src/content/chapters/<chapterId>.json`）

段落の配列。注釈対象はインラインマークアップで表す。

```json
{
  "workId": "crime",
  "chapterLabel": "第一部 第一章",
  "order": 1,
  "paragraphs": [
    { "id": "p001", "src": "В начале июля...", "ja": "七月はじめ...", "status": "draft" }
  ]
}
```

- `src` は原文。v1では表示しないが突き合わせのために必ず持つ
- `status` は `draft` / `checked` / `reviewed`。`reviewed` は人間が原文と照合済み
- 段落IDは一度振ったら変えない。読書位置と注釈の参照先になる

### インラインマークアップ（3種類だけ。増やさない）

| 記法 | 意味 | 表示 |
|---|---|---|
| `{{p:id\|表示}}` | 固有名での言及 | 実線下線。愛称・父称形のときだけ本名グロス |
| `{{r:id\|表示}}` | 代名詞・普通名詞での言及 | **既定では無印**。タップのみ効く |
| `{{n:id\|表示}}` | 語注 | 点線下線 |

**`r` にグロスを出してはいけない。** 「彼〔ラスコーリニコフ〕」が全段落に出る状態は読者をなめている。
設定で薄い印を出すオプションだけ用意する（既定オフ）。

グロスを出す条件は `p` かつ 表示文字 ≠ `short` かつ ≠ `name` のときだけ。

### 人物台帳（`src/data/works/<workId>/people.json`）

`aliases` は**手で管理する**。姓・名・父称・愛称・指小形の対応は、間違えると読者を直接ミスリードする。
LLMに任せない。

### 語注台帳（`src/data/works/<workId>/glossary.json`)

`verified: false` の注釈はUIに**「未検証」**と表示する。裏取りしていない情報を確定的に見せない。

## 3. パイプライン（`tools/`）

ビルドから切り離した手動実行のスクリプト群。**生成結果は必ず git にコミットする。**
`npm run build` の中でLLM APIを呼ばないこと（ビルドのたびに訳文が変わり、差分レビューが成立しなくなる）。

- `wikisource-to-paragraphs.ts` / `fb2-to-paragraphs.ts` — 原文→段落スケルトン。`<emphasis>` は `em` フラグとして残す（注釈を当てる位置の目印）
- `translate.ts` — 段落単位で翻訳。style-guide・people の表記一覧・直前3段落の訳を毎回プロンプトに同梱（章をまたいだ文体の一貫性のため）
- `check-alignment.ts` — 数量・否定・文数・固有名詞表記の機械チェック。人間が読む前のふるい。CIで落とさない
- `extract-annotations.ts` — 注釈の**候補**を出すだけ。台帳への反映は人間がやる。自動で glossary.json に書き込まない

## 4. サイト実装

- Astro、静的出力。UIフレームワークは入れない（読書画面のインタラクションはDOM操作で足りる）
- `astro.config.mjs` に `site` と `base` を必ず設定（GitHub Pages のサブパス配信対策）
- Content Collections（zod）で記法違反・存在しないID参照をビルド時に落とす
- マークアップのパーサは正規表現1本。凝らない

### 読書画面の要件

- **登場人物レール**: PCでは左に常駐、モバイルでは上部横スクロール帯。IntersectionObserver で
  可視段落を追い、いま画面に出ている人物だけを点灯。タップで人物カード
- **注釈カード**: 人物=正式名・原語表記・呼ばれ方一覧・立場・関係・補足／語注=見出し・本文・出典・未検証バッジ。
  PCはポップオーバー、モバイルはボトムシート。Esc と背景タップで閉じる
- **設定**: 文字サイズ4段階・行間3段階・愛称グロス（既定オン）・代名詞マーク（既定オフ）・
  縦書き・夜モード。設定と読書位置（章ID+段落ID）は localStorage に保存
- **アクセシビリティ**: 注釈は `<button>`。フォーカスリングを消さない。`prefers-reduced-motion` 尊重。
  色だけに依存しない（実線/点線が形の区別を担う）

### デザイントークン

```css
--paper: #E7E4D8;  /* 緑みのある古紙。クリーム寄りにしない */
--ink:   #1B1A17;
--person:#2E4A43;  /* 深緑 = 人物 */
--note:  #9A7415;  /* 黄 = 語注 */
```

色は役割に紐づける。緑は人物、黄は語注。崩さない。本文は明朝、UIはゴシック。本文の最大幅は 34em。

## 5. マイルストーン

| | 内容 | 完了条件 |
|---|---|---|
| M0 | 骨組み | GitHub Pages にデプロイされ、`base` 込みでアセットが解決している |
| M1 | ビューア | レール、カード、設定、縦書き、位置保存が全部動く |
| M2 | パイプライン | 原文から第一章の段落配列が生成され、翻訳スクリプトが通る |
| M3 | 第一章の完成 | 全段落が `reviewed`。注釈が全て `verified`。**1章あたりの所要時間を実測して記録** |

M3の実測値が全体の見積もりになる。この数字が出るまで残りの章に手をつけない。

## 6. 著作権

- パブリックドメインの原文のみ扱う（著者没後の保護期間満了をロシア・日本・米国等で確認）
- **既存の日本語訳をコピーしない。** 参照もしない。訳出は原文からやる
- 注釈は出典を書く。裏取りしていないものは `verified: false` のまま公開してよいが、そう表示する
- フッターに底本と、訳文がAIを用いた新訳である旨を明記する
