# 読解支援レイヤー（注釈）の作業手順（注釈エージェント用）

1つの章に人物マークと語注を当てる。作業ディレクトリはリポジトリのルート。

**このレイヤーがサイトの中心価値である。** 訳文の良さではなく、
「日本語にしただけでは越えられない段差」（当時の制度・貨幣・官等・宗教・風物・慣用句・
原語の語義）を読者に渡すために付ける。原文そのものの難しさ（長い独白・冗長さ）は解かない。

## 材料（これ以外を読まない）

- `source/annotations/ja/<chapterId>.txt` — 対象章の訳文。**セグメント番号つき**
  （`npx tsx tools/export-ja.ts <chapterId> --segments` で生成。原文は含まれない）
- `src/data/works/<workId>/people.json` — 人物の正式表記と id
- `src/data/works/<workId>/glossary.json` — **既存の語注**。同じ語には既存 id を使い回す
- `src/data/works/<workId>/style-guide.json` の `terms` / `names` — 訳語と音写の台帳

原文（ロシア語等）は読まない・書かない。応答にも出力にも転記しない。

## 付け方の方針

インラインマークアップは3種だけ。増やさない。

| 記法 | 意味 | 付ける場所 |
|---|---|---|
| `{{p:id\|表示}}` | 固有名での言及 | **その呼び方が初めて出る1箇所だけ** |
| `{{r:id\|表示}}` | 代名詞・普通名詞での言及 | ごく控えめに。1章に1〜2個 |
| `{{n:id\|表示}}` | 語注 | 下記の基準に当たる語 |

- **人物マークは呼び方ごとに初出1回。** 同じ呼び方が何度出てもくり返し付けない
  （『駅長』の実績: 「ドゥーニャ」は本文に39回出るがマークは3つ＝異なる呼び方が3種あったから）。
  愛称形・父称形・full name はそれぞれ別の「呼び方」として1回ずつ付ける
- **語注を付ける語**: 当時の制度・官等・身分呼称／貨幣・度量衡／宗教と暦／衣食住と器物／
  地名・建物／民話・聖書・詩からの引用／慣用句／原語の語義が訳語に収まりきらない語
- **語注を付けない語**: 現代日本語として普通に読める語、文脈で分かる語、
  物語の解釈（「〜を象徴する」等）。解釈は書かない
- 1段落に何個も付けない。目安は**本文30〜45段落あたり語注25〜35個**
- 語注 id は英小文字・数字・ハイフンのみ。原語のラテン翻字か内容で名づける（`dvugrivenny`, `pech`）
- `body` は60〜200字。**断定できないことは書かない。**裏が取れていない事項は
  `sources` に `"要確認: …"` と書き、`verified` は `false` のまま出す（UIに未検証バッジが出る）
- **語注台帳は作品単位なので、短編集では同じ id が複数の編で共有される。**
  だから `body` に「ここでは〜」「この場面では〜」のような**その編に固有の文脈を書かない**。
  通貨・度量衡・官等・器物のような共有されやすい語は、語そのものの説明だけを書く。
  どうしてもその編固有の説明が要るなら、その編だけで使う別の id を立てる
  （`ruble`（通貨の説明）とは別に `desyat-rubley`（その額の意味）を立てる、等）
- `term` は**見出し語**（「ルーブル」）。本文中の表示文字（「十ルーブル」）とは別でよい。
  同じ id を別の `term` で定義するとマージが落ちるので、見出し語は語の基本形にする

## 出力（2ファイル）

### 1. 語注の定義 `source/annotations/<chapterId>.glossary.json`

```json
{
  "dvugrivenny": {
    "term": "二十コペイカ",
    "body": "двугривенный は二十コペイカ硬貨の通称。…",
    "sources": ["要確認: 1880年代の相場"],
    "verified": false
  }
}
```

既存 `glossary.json` にある id はここに再定義しない（使い回すだけ）。

### 2. 注釈の位置 `source/annotations/<chapterId>.marks.json`

```json
[
  { "p": "p002", "seg": 2, "text": "辻馬車の御者", "kind": "n", "id": "izvozchik" },
  { "p": "p002", "seg": 2, "text": "イオーナ・ポターポフ", "kind": "p", "id": "iona" }
]
```

- `seg` は材料ファイルの `[0]` `[1]` … の番号
- `text` は**そのセグメントにちょうど1回だけ現れる文字列**。2回以上現れるなら前後を含めて伸ばす
- 本文の文字列は自分で書き写さず、材料ファイルからそのままコピーする
  （章JSONの本文は改変ゼロを機械保証しているので、一字違うと落ちる）

## 検証（必須。両方 exit 0 まで直す）

```bash
python3 tools/marks-to-markup.py <chapterId>
npx tsx tools/apply-annotation.ts <chapterId> source/annotations/<chapterId>.markup.json \
  --glossary source/annotations/<chapterId>.glossary.json
```

`marks-to-markup.py` は位置指定が一意でなければ落ちる。`apply-annotation.ts` は
マークアップを剥がした本文が元と一字も違わないことを検査する。

作業後、作品の語注台帳へ取り込むのはオーケストレータの仕事:

```bash
python3 tools/merge-glossary-fragments.py <workId>
```

## 報告

最後の応答は `done <chapterId> 語注N 人物M 参照K` の1行だけ。本文の引用を含めない。
