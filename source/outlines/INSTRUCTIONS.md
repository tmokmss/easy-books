# 章アウトライン生成の作業手順（要約エージェント用）

『罪と罰』読解支援サイトの「階層ズーム・リーダー」用に、1つの章の節区切りと要約を作る。
作業ディレクトリはリポジトリのルート。

## 材料（これ以外を読まない）

- `source/outlines/ja/<chapterId>.txt` — 対象章の本文（段落ID・字数付き）
- `src/data/works/crime/people.json` — 人物の正式表記

**対象章以外の章、他章のアウトライン、原文（ロシア語）は読まない。**
ネタバレ封じ込めのため、材料を対象章だけに構造的に制限している。
作品について事前に知っている展開・結末・人物の運命を要約に持ち込まないこと。
本文にないことは書かない。

## 作る順序（ボトムアップ厳守）

1. **段落要約** — 本文がおおむね100字以上の段落に、40字目安（上限60字、必ず本文より短く）。
   その段落に書かれていることだけを書く。短い段落・一言の台詞には作らない。
2. **節の区切り** — 章全体を5〜15段落の節に**過不足なく連続分割**する
   （最初の節は最初の段落から、次の節は前の節の直後から、最後の節は最後の段落まで）。
   切れ目の基準: 場所が変わる／時間が飛ぶ／登場人物の組み合わせが変わる／地の文と長い独白の切り替わり。
   label は15字以内の場面見出し。その節より後の展開を label に含めない。
3. **節要約** — 150字目安（上限225字）。材料は 1. の段落要約とその節の本文だけ。
   **その節の終端までに読者が知り得た情報だけで書く。**「後に〜することになる」等の先取りは厳禁。
4. **章要約** — 300字目安（上限450字）。材料は 3. の節要約だけ（本文に戻らない）。
   章の終端までの情報だけで書く。

## 文体

- 常体（だ・である）。現在形基調。要約どうしで固有名詞の表記を揺らさない。
- メタ言及禁止:「この章では」「本節では」「物語は」「描かれる」等。
- 人物名は people.json の `short`（例: ラスコーリニコフ、ソーニャ、ラズミーヒン）。
  ただし本文がまだ名を明かしていない段階の要約では、本文の呼び方（「青年」等）に従う。
- 金額・年齢・日数などの数値は本文にあるものだけを、本文の表記のまま使う。

## 出力

`source/outlines/<chapterId>.json` に次の形で書く（status や coversUpTo は書かない。ツールが付ける）:

```json
{
  "sections": [
    { "label": "見出し", "range": ["p001", "p007"], "summary": "150字目安…" }
  ],
  "chapterSummary": "300字目安…",
  "paragraphSummaries": { "p001": "40字目安…" }
}
```

## 検証（必須）

```bash
npx tsx tools/merge-outline.ts <chapterId> source/outlines/<chapterId>.json
```

error が無くなる（exit 0）まで出力を修正して再実行する。warn は許容するが、
節サイズの warn が出たら区切りを見直す材料にすること。
成功すると `src/content/outlines/<chapterId>.json` が生成される。

最後の応答は `done <chapterId> 節N 段落要約M` の1行だけ。本文の引用を応答に含めない。
